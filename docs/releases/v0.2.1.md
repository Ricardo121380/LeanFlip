LeanFlip v0.2.1 修正了 Codex 请求地址的显示，并首次发布到 npm。

## 修复

- **Codex 地址显示错误**：Codex 使用官方渠道（配置里没有 `model_provider`）时，如果 `config.toml` 里还留着以前的 `[model_providers]` 表，首页和光路会把那张表的地址当成正在使用的地址；测连通、检查模型和命令行的连接信息也会用错地址。现在和 Codex 的规则一致：没写 `model_provider` 就是官方渠道，没被选中的表不算。

## 新的安装方式

- **npm**：`npm install -g leanflip`，提供 `leanflip`（命令行与 TUI）和 `leanflip-app`（下载、安装桌面 App）两个命令。需要 Node.js 20 或更新版本；原生程序从本页下载，并按包内固定的 SHA256 校验。
- **Homebrew**：

  ```sh
  brew tap ricardo121380/leanflip https://github.com/Ricardo121380/LeanFlip.git
  brew install --cask ricardo121380/leanflip/leanflip-app   # 桌面 App（macOS Apple Silicon）
  brew install --cask ricardo121380/leanflip/leanflip       # 命令行与 TUI
  ```

## 下载

| 平台 | 桌面 App | 命令行与 TUI |
| --- | --- | --- |
| macOS Apple Silicon（M 系列） | `leanflip_0.2.1_macos-arm64.dmg` | `leanflip_0.2.1_macos-arm64.tar.gz` |
| Linux x86_64（Ubuntu 24.04 构建） | `leanflip_0.2.1_linux-x64.deb` | `leanflip_0.2.1_linux-x64.tar.gz` |

从 0.2.0 升级：退出 App 后用新版本覆盖即可，数据不受影响。

**macOS 首次打开：** App 和命令行没有 Apple 签名与公证，第一次运行会被系统拦下。App 在提示后进入“系统设置 → 隐私与安全性”，点“仍要打开”；命令行在解压目录执行 `xattr -d com.apple.quarantine leanflip`。

## 已知限制

- 统计页“对比前 30 天”的变化幅度可能偏大：Claude Code 和 Gemini CLI 默认只保留 30 天记录，前一段的数据往往不全。
- 切换记录从 0.2.0 开始积累，更早的用量大多显示为“归不到供应商”。

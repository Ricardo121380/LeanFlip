LeanFlip v0.3.5 新增“同步到其他 Agent”：把一张中转卡片的地址和 Key 一次加到其他工具里。额度方面，托管的 Codex 账号可以自动刷新，光路视图显示额度，终端新增 `leanflip quota`。

## 同步到其他 Agent

- 第三方供应商那一行新增“同步”按钮，新增或复制卡片保存后也会自动打开。LeanFlip 按每个目标工具自己的预设生成卡片，地址、Key 和名称来自原卡片。
- 目标工具支持同一种协议时标“直接可用”，并沿用原来的模型。协议不同时标“需要检测”，例如 Codex 走 Responses、Claude Code 走 Anthropic Messages：中转站要同时支持另一种协议，模型也要重新选。这时可以先“获取模型”“检测”，再添加。
- 已经有相同地址和 Key 的工具标“已存在”。默认一个都不勾选，只添加卡片；勾选“同时设为当前 / 同时启用”才会切换。部分工具添加失败时，对话框保留已成功的结果，重试只补失败的那些。
- 同步出来的卡片互相关联。之后在任意一张上改 Key，保存时会提示把仍在用旧 Key 的关联卡片一起改掉。
- Key 写成环境变量引用（如 `{env:NAME}`、`${NAME}`）的卡片不能同步，避免把引用原样写进不认这种写法的工具。

## 额度

- 设置新增“托管 Codex 账号自动刷新额度”，可选每 15 分钟或每小时，默认关闭。距上次结果满一个间隔才联网查询，本机会话记录里的结果也算。
- 光路视图的服务端点旁显示额度标记，每个额度来源一个，颜色规则和清单视图一致：过 80% 变黄，用完变红。
- 命令行新增 `leanflip quota`：

```sh
leanflip quota            # 读本机记录和缓存，不联网、不写文件
leanflip quota --refresh  # 联网查询托管账号和已设置平台的中转卡
leanflip quota --json     # 输出完整结果
```

输出包含来源、使用它的卡片、各窗口用量或余额、状态和更新时间，不输出 Key 或登录凭据。

## 验证与升级

合入前已通过 macOS 与 Linux 的 Rust 测试、前端测试、TypeScript 类型检查、Clippy、CLI 菜单和 TUI 检查及桌面打包检查。发布安装包由 GitHub Actions 构建，并附带 `SHA256SUMS`。

从 0.3.4 升级时，退出 App 后覆盖安装即可，现有供应商、场景、账号和客户端配置继续使用。

- npm：`npm install -g leanflip@0.3.5`。通过 npm 安装器管理桌面 App 的用户，退出 App 后执行 `leanflip-app install --replace`；自定义安装目录时继续使用原来的 `--app-dir`。
- Homebrew：`brew update`，再升级已安装的 `ricardo121380/leanflip/leanflip` 或 `ricardo121380/leanflip/leanflip-app` Cask。
- 下载附件：macOS Apple Silicon 的 `.dmg` 与 CLI `.tar.gz`，以及 Linux x86_64 的 `.deb` 与 CLI `.tar.gz`。

macOS App 和 CLI 仍未做 Apple Developer ID 签名与公证；首次运行说明见 [README](https://github.com/Ricardo121380/LeanFlip/blob/v0.3.5/README.md#安装)。

LeanFlip v0.3.9 修复配置、凭据与账号删除中的安全边界问题，补齐终端创建供应商、Shell 补全和额度查询子路径支持。

## 配置与凭据保护

- 设置文件损坏时停止启动并显示错误，不再静默使用默认目录继续写入（#51）。请先修复或从备份恢复设置文件再启动。
- Codex OAuth 账号删除及清空使用事务日志，支持失败恢复，避免账号库和实时凭据处于半删除状态；外部修改的凭据不会被误删（#50）。
- Claude `apiKeyHelper`、云认证辅助命令及 Codex `auth.command` 在写入客户端前需要本机明确授权。授权绑定命令与相关配置，导入卡片或恢复备份不会带入授权（#44、#45）。CLI 可用 `leanflip provider trust-commands <tool> <id>` 预览，再按输出的指纹授权。
- 备份恢复默认不恢复路径；启用后会展示当前目录、目标目录和解析后的真实路径，必须确认，且路径变化后需要重新确认（#46）。
- Hermes 清空 API Key 后不会再合并回旧密钥；Gemini 官方登录配置的导入与往返切换保留模型选择（#33、#34）。

## 终端与首次配置

- Menu 新增“新建供应商”，TUI 使用 `n`，也可运行 `leanflip provider create <tool>`。覆盖 10 类工具，支持可编辑 ID、隐藏密钥、可选模型、保存前预览和取消；默认只保存，不激活（#26）。
- `leanflip completions <shell>` 支持 Bash、Zsh、Fish、PowerShell、Elvish；生成补全不读取或迁移用户配置（#31）。
- 设置页和 `leanflip claude-onboarding` 提供一次性的 Claude 引导完成标记操作。预览确认后仅在默认 `~/.claude.json` 写入 `hasCompletedOnboarding: true`，保留其他内容并纳入首次写入备份；切换供应商不会自动执行（#27）。此操作不登录账号，暂不支持 `CLAUDE_CONFIG_DIR` 自定义目录。

## 额度、统计与分发

- 额度设置新增可选“查询基址”，支持保留明确指定的子路径；留空时继续自动探测。查询基址须与模型地址同源，避免跨站发送凭据（#29）。
- OpenCode 用量扫描可从数据库替换、时间回退中恢复，并处理相同时间戳的新增消息而不重复计数（#49）。
- 文件监听忽略内部 `.leanflip-write-` 临时文件（#28）。
- npm 包声明支持 macOS 与 Linux，其他操作系统会在安装阶段收到不支持提示；原生附件仍为 macOS ARM64、Linux x64（#30）。
- macOS App 增加完整 ad-hoc 签名与资源封印，构建流程执行严格签名校验，修复已观察到的资源签名缺失问题（#25）。这不等同于 Apple Developer ID 签名或公证，Gatekeeper 仍可能拦截。

## 验证与升级

本批次通过 Rust、前端、安装器测试，Menu/TUI 真实伪终端回归，以及类型与静态检查。发布附件由 GitHub Actions 分别在 macOS ARM64、Linux x64 构建，附带 `SHA256SUMS`。

- npm：`npm install -g leanflip@0.3.9`。通过 npm 管理桌面 App 时，退出 App 后执行 `leanflip-app install --replace`；自定义目录继续使用原来的 `--app-dir`。
- Homebrew：`brew update`，再升级已安装的 `ricardo121380/leanflip/leanflip` 或 `ricardo121380/leanflip/leanflip-app` Cask。
- 附件：macOS Apple Silicon `.dmg` 与 CLI `.tar.gz`；Linux x86_64 `.deb` 与 CLI `.tar.gz`。

退出 App 后覆盖安装，继续使用现有供应商、场景和账号。含凭据辅助命令的配置需要按新流程在本机重新授权。macOS 首次运行说明见 [README](https://github.com/Ricardo121380/LeanFlip/blob/v0.3.9/README.md#安装)。

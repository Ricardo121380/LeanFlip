# LeanFlip v0.4.2

修复供应商配置保护、导入恢复、跨工具同步、模型检查和用量统计中的问题。

## 配置与凭据保护

- 离开无法识别登录身份的 Codex 官方卡片时，不再删除其他暂存登录（#67）。
- 切换 Codex 卡片时保留外部 `model_catalog_json`；手写的 `model_providers.custom` 冲突表会保存在独立名称下，并同步调整非活动 profile 的引用，活动 profile 保持目标路由，不把旧凭据合入新路由（#68、#69）。
- 修改或清空 Codex API Key 时，同时清理旧 bearer 字段，避免旧 Key 再次生效（#79）。
- 通用配置保存使用同一份文件快照计算修订和补丁，检测到并发外部修改时拒绝覆盖（#74）。
- TOML 编辑正确处理多行字符串、数组和注释，修改模型时不会误改 `developer_instructions` 中的示例（#75）。
- 命令授权提示明确其边界：只绑定配置中的命令、包引用和相关连接信息，不锁定可执行文件内容、继承的 PATH 或客户端运行目录，也不在客户端实际执行时再次验证。本次为边界说明，不提供运行时可执行文件锁定（#65）。

## 导入、恢复与同步

- 从 CC Switch 导入或从备份恢复的卡片默认关闭额度自动刷新，需在本机重新开启；不禁止用户主动配置本地服务（#66）。
- 备份预览显示托管账号绑定，恢复前检查实际待恢复卡片引用的账号是否可用，避免产生悬空绑定；保留被跳过的本机卡片及场景引用行为（#71）。
- 修正冲突卡片重命名导入的状态和数量摘要（#73）。
- 同步前校验来源卡片快照，仅更新同步关联信息；旧弹窗不会覆盖已经更新的源配置；新建 Krill 卡片完成登录后可立即同步（#80）。
- 保留 Gemini 显式选择的 Vertex AI、API Key 或个人登录方式，包括未写入 `.env` 的配置（#76）。
- OpenCode 2.x 修改地址和 Key 时写入实际生效的 `settings` 字段；接受部分 capabilities 配置，并显示无效条目的跳过原因（#81、#82）。

## 检测与用量

- 检查模型时验证协议响应结构，HTTP 200 的 HTML、空对象或其他协议响应不再被误判为成功（#77）。
- 用量扫描增加单行、单文件和总读取预算；超限会提示，保留已经处理的进度；超长 JSONL 行分段跳过，后续有效记录仍可读取（#70）。
- 完整 JSONL 末尾没有换行也可统计；未完成的尾部仍等待后续写入（#72）。
- 统计 Gemini 嵌套子代理会话（#78）。
- Hermes 请求数改为累计估算值之差，避免扫描批次改变结果；消息数和 token 分批到达时也保留请求数。本版不自动重算已缓存的历史偏差（#83）。

继续提供 macOS Apple Silicon、Linux x64、Windows x64 桌面与 CLI 安装包，以及 Homebrew/npm 安装入口。附件校验值见 `SHA256SUMS`。macOS 程序仍未做 Developer ID 签名及公证。

本批次不包含尚未验证的 #58、#84、#85。

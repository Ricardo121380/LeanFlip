LeanFlip v0.3.4 新增场景：把多个工具的供应商选择保存成一组，在首页、命令面板、托盘或终端中一次应用。例如“工作”场景让 Claude Code 和 Codex 使用同一家中转，同时启用 OpenCode 的另一张卡片。

## 创建与应用场景

- 在首页打开“场景”，把当前配置保存为场景，也可以编辑名称、各工具的供应商选择和提醒规则。
- 应用前可以预览每个工具将发生的变化，并选择本次要应用的工具。场景只记录供应商卡片的引用，不另外复制密钥和连接配置。
- 单选式工具切换当前供应商；并存式工具按场景启用或移出 LeanFlip 管理的卡片，保留用户直接在客户端添加的条目。未列入场景的工具保持原样。
- 首页显示当前场景；手动切换某个工具后，会标记场景“已偏离”。引用的卡片已被删除或客户端配置无法读取时，会显示对应提示。
- 应用后可以撤销。各工具逐个执行，某个工具失败不会阻止其他工具；结果会列出失败及未能完整恢复的部分。多个工具之间不保证同时成功或同时回滚，撤销也会重新执行切换。

## 快捷入口与提醒

- 命令面板 `⌘K` / `Ctrl+K` 可以搜索并应用场景。
- App 窗口在前台时，`⌘⇧1–9`（其他平台为 `Ctrl+Shift+1–9`）直接应用前九个场景，并提供撤销提示。
- 托盘新增场景子菜单，标记当前匹配的场景和偏离状态；从托盘应用后的结果会同步到窗口。
- 提醒规则支持每周时间段、本机网段（CIDR）和内网域名。后台每分钟检查一次，条件开始满足且尚未使用该场景时提醒切换，不会自动改动配置。

## 命令行与备份

```sh
leanflip scene list
leanflip scene show "工作"
leanflip scene apply "工作"
leanflip scene apply "工作" --tool codex
```

场景在桌面 App 中创建和编辑，终端用于列出、预览和应用。部分工具应用失败时，CLI 输出各工具的结果并返回退出码 1（`scene.partial`）。

加密备份包含场景。恢复时合并场景，跳过相同 ID 或名称的条目；供应商因 ID 冲突而以新 ID 恢复时，场景引用会同步调整。

## 验证与升级

场景功能合入前已通过 macOS 与 Linux 的 Rust 测试、前端测试、TypeScript 类型检查、Clippy、CLI 菜单和 TUI 检查及桌面打包检查。发布安装包由 GitHub Actions 构建，并附带 `SHA256SUMS`。

从 0.3.3 升级时，退出 App 后覆盖安装即可，现有供应商、账号和客户端配置继续使用。

- npm：`npm install -g leanflip@0.3.4`。通过 npm 安装器管理桌面 App 的用户，退出 App 后执行 `leanflip-app install --replace`；自定义安装目录时继续使用原来的 `--app-dir`。
- Homebrew：`brew update`，再升级已安装的 `ricardo121380/leanflip/leanflip` 或 `ricardo121380/leanflip/leanflip-app` Cask。
- 下载附件：macOS Apple Silicon 的 `.dmg` 与 CLI `.tar.gz`，以及 Linux x86_64 的 `.deb` 与 CLI `.tar.gz`。

macOS App 和 CLI 仍未做 Apple Developer ID 签名与公证；首次运行说明见 [README](https://github.com/Ricardo121380/LeanFlip/blob/v0.3.4/README.md#安装)。
